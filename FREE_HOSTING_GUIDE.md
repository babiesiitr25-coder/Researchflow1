# Deploy ResearchFlow free: GitHub + Neon + Render

This guide is for the included ResearchFlow Node/Express + PostgreSQL application. It does **not** require Replit. The website is not deployed just by downloading this ZIP.

**Free-plan limitations:** Render Free Web Services sleep after about 15 minutes of inactivity and may take about a minute to restart. Neon Free currently provides 1 GB of PostgreSQL storage per project and monthly compute/network limits. The application stores uploads *inside PostgreSQL* as binary data, so only upload smaller research files (individual uploads are capped at 15 MB). Do **not** use this service as the only copy of important manuscripts/results. Configure regular exports/backups. OpenAI API usage, if enabled, is billed separately. Free quick-command mode works without an API key.

## 1. Create a free Neon PostgreSQL database

1. Go to https://console.neon.tech/ and create a free account.
2. Create a project named `researchflow`, with a nearby region if available.
3. Select **Connect**, choose the main database and copy the **PostgreSQL connection string**. It looks like `postgresql://USER:PASSWORD@HOST/DB?sslmode=require`.
4. Do not post this string in chat or upload it to GitHub. It is a secret. Keep the TLS settings in the copied URL.

## 2. Upload this app to a private GitHub repository

1. Go to https://github.com/new and create a **private** repository, e.g. `researchflow`.
2. Extract this ZIP locally. Upload the *contents* of the extracted folder to the **root** of the repo, including the `public` folder, `package.json`, `server.js`, `render.yaml`, and `README.md`.
3. Use **Add file > Upload files**, or push with Git. Check that GitHub displays `server.js` directly at the root, *not* within another nested folder.
4. Never upload `.env` files, keys, passwords, or database connection strings. `.env.example` is safe as it contains placeholder values only.

## 3. Deploy a free Render Web Service

1. Go to https://dashboard.render.com/ and create an account.
2. Click **New > Web Service**. Connect GitHub and select your private `researchflow` repository.
3. Set the following values:

   - Name: `researchflow-collaboration` (choose a unique name if required)
   - Language/runtime: `Node`
   - Instance: **Free** ($0)
   - Build command: `npm install`
   - Start command: `npm start`
   - Root directory: blank (the repository root)

4. Under **Environment**, add the following keys and values (Render Secrets, not in code):

   | Key | Value |
   | --- | --- |
   | `DATABASE_URL` | Full secret connection string copied from Neon |
   | `SESSION_SECRET` | A random 64+ character secret generated by a password manager or by the Node command below |
   | `OWNER_EMAIL` | Your email address |
   | `OWNER_PASSWORD` | A unique password at least 12 characters long |
   | `OWNER_NAME` | Your display name (optional) |
   | `NODE_ENV` | `production` |
   | `PGSSL` | `true` |

   On a computer with Node installed, generate a random `SESSION_SECRET` using: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`. Do not share it.

5. Click **Deploy Web Service**. Once the deployment logs show `ResearchFlow listening on port ...`, Render supplies a public HTTPS URL such as `https://your-project-name.onrender.com`. No domain purchase is needed.
6. Open this URL and sign in with `OWNER_EMAIL` and `OWNER_PASSWORD`.
7. Use **Invite / team** to create a one-time collaborator invitation and privately share the link with your IIT Delhi colleague. It expires in seven days.
8. Test from a second browser and verify that task updates and notes appear for both users.

Alternative: `render.yaml` is included for **New > Blueprint** deployments; Render will prompt for the missing secret values. Do not add a Render Postgres Free database as part of the Blueprint; that service expires after 30 days. Use the persistent Neon Free database connection as described above.

## 4. Quick prompts, free vs paid

Free built-in quick commands:

- `Add task: Derive pulse shape factor for a triangular load`
- `Note: Validated Boussinesq influence factor today`
- `Started [matching task title]`
- `Completed [matching task title]`
- `Show progress`

For more flexible AI interpretation and PDF/DOCX summaries, optionally add `OPENAI_API_KEY` to Render's Environment settings. That invokes a metered API, not ChatGPT subscription credits. Do not add the key if you want strictly zero API cost.

## 5. Troubleshooting

- **Missing environment variable**: add each required key to Render Environment and redeploy.
- **SSL / Postgres connection error**: retain `sslmode=require` in the Neon URL, keep `PGSSL=true`, and verify the credential copy.
- **Site slow after inactivity**: expected Render Free cold start.
- **Upload rejected**: each file must be 15 MB or smaller; database capacity is limited.
- **App loads but cannot log in**: check Render logs for database initialization and that owner credentials were entered correctly. The owner account is created only on initial database setup; changing `OWNER_PASSWORD` later does not automatically reset an existing database password.
- **No automatic AI responses**: without `OPENAI_API_KEY`, commands use the free deterministic interpreter; they are not powered by an LLM.

## Privacy and data retention

This is a private-login web application hosted on third-party services, not on institutional infrastructure. Do not upload confidential, unpublished, or restricted research materials without approval from relevant collaborators/institutions. A public HTTPS web URL is not the same thing as a private institutional deployment; the app restricts research data through login. Keep backup copies of notes and small uploads. The starter does not include automated backup scheduling or institutional single-sign-on.
